# S-0 空席スパイク — ANA特典カレンダー 構造調査用の拡張

My 8flyer 立て直しの **S-0**。「ANA の特典カレンダーを機械的に読めるか」を確定するためだけの、**使い捨ての調査用拡張**です。

---

## この拡張がやること / やらないこと

| | 内容 |
|---|---|
| ✅ やる | 画面右下にボタンを出す |
| ✅ やる | 押されたら、**今表示されている画面の HTML** を全フレームぶん読み取る |
| ✅ やる | それを1つの JSON にまとめ、**あなたのダウンロードフォルダに保存する** |
| ❌ やらない | フォームへの書き込み |
| ❌ やらない | 「検索する」等のボタンのクリック |
| ❌ やらない | ページ遷移・リロード・自動巡回 |
| ❌ やらない | 外部サーバーへの送信（保存先はローカルのみ） |

`manifest.json` の権限は `scripting` と ANA 2ドメインの `host_permissions` だけです。

---

## 入れ方

1. Chrome のアドレスバーに `chrome://extensions/` を入力
2. 右上の「**デベロッパーモード**」をオンにする
3. 「**パッケージ化されていない拡張機能を読み込む**」をクリック
4. このフォルダ（`spike-ana-calendar/`）を選択
5. 一覧に「My 8flyer — 特典カレンダー調査（読み取り専用）」が出れば完了

> 既存の「My 8flyer → ANA Bridge」拡張と**同時に入れても干渉しません**（ボタンのIDもCSSも別）。

---

## 使い方

ANA にログインし、`aswbe-i.ana.co.jp` の **特典予約**画面を開いた状態で使います。
右下に**青い「📋 この画面を保存」ボタン**が出ます（既存の ana-bridge のオレンジ色ボタンの1段上）。

押すと「保存しました（フレーム N件 / 合計 NNKB / 記号を含むフレーム N件）」と表示され、
ダウンロードフォルダに `m8f-ana-calendar_YYYYMMDD-HHMMSS.json` ができます。

### 空席の情報源は2つある（役割が違うので両方使う）

| | **特典カレンダー** | **空席検索** |
|---|---|---|
| URL | `cam.ana.co.jp/psz/tokutencal/form.jsp` | `aswbe-i.ana.co.jp/.../award/search/` |
| 取れる範囲 | 路線 × 搭乗日を**一気に**（数か月分） | 1回7日分（前後3日を比較） |
| 対象 | **ANA自社便のみ** | 提携航空会社便も含む |
| 精度 | 「目安」（公式に「実際の予約可能座席数と異なる場合があります」と明記） | 実在庫に近い |
| 粒度 | ◎（十分空席あり）／○（空席あり）／△（残席わずか）／―（利用不可）／!（キャンペーン期間） | 便名・時刻つき |

**設計方針：面を特典カレンダーで取り、点を空席検索で確定する。**
優先は特典カレンダー。精度ではなく**ANAを叩く回数が桁違いに少なくて済む**ため（規約リスクと先方負荷が最小）。

### 撮ってほしい画面（優先順）

| # | 画面 | 操作 | 何が分かるか |
|---|---|---|---|
| **A** ★ | 特典カレンダー（**データ表示済み**） | Zone で目的地（例：欧州）を選び、クラス「エコノミー」を押す → 表が出たら 📋 | 日付と ◎○△― の対応の取り方 |
| **B** | 同カレンダーの**別クラス** | 続けて「ビジネス」を押す → 📋 | クラス切替がURL遷移か裏での再取得か。**1回で4クラス取れるかが決まる** |
| **C** | 空席検索の結果 | 往復タブで区間・日付を入れ、**「前後3日の空席を比較」にチェック**して検索 → 📋 | 便名・時刻と実在庫の出方 |

> ⚠️ 「条件を選択してください。」と表示されている状態で撮っても中身が空です。**必ず表が出てから**押してください。

> 💡 検索履歴に **東京(羽田)⇔フランクフルト / フランクフルト⇔リスボン** が残っていました。
> C はその区間で構いません（実際に狙っている旅程のほうが、後の設計に効きます）。

## 保存される JSON の中身

```jsonc
{
  "_meta": {
    "capturedAt": "2026-09-04T...",
    "topUrl": "https://aswbe-i.ana.co.jp/...",
    "frameCount": 2
  },
  "frames": [
    {
      "frameId": 0,
      "url": "...",
      "title": "...",
      "html": "<html>…レンダリング後のDOM全体…</html>",
      "textLength": 4821,
      "symbolCounts": { "○": 12, "△": 5, "×": 9 }   // 手応え用の概算
    }
  ]
}
```

`symbolCounts` は「取れていそうか」を即座に見るための概算で、**判定には使いません**。実際のセレクタは Claude が `html` を読んで確定します。

---

## 注意

- **JSON には ANA のログイン後の画面がそのまま入ります。** 予約番号・氏名・マイル残高などが含まれる可能性があるため、**第三者に渡さないでください**（Claude に渡すぶんには、ローカルのファイルを読むだけです）
- 調査が終わったらこの拡張は削除して構いません（`chrome://extensions/` から削除）

---

## 調査が終わったら

Claude が JSON を解析し、次のどちらかを報告します。

- **読める** → 本実装（S-6 availability）へ進む。既存の ana-bridge 拡張に収集機能を足す
- **読めない** → 空席の入力を「手入力の記録UI」に切り替える設計へ変更する（計画に織り込み済み）

正本の計画：`~/.claude/plans/noble-swimming-blossom.md`
